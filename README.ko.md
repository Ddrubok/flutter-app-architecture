# Flutter 앱 구조 설계

[English](README.md)

Flutter 앱에서 사용자의 동작이 화면에서 시작해 데이터 저장까지 어떻게 이어지는지 설계합니다.

```text
$flutter-app-architecture 습관 기록 앱에서 사용자가 저장을 누르자마자 화면을 닫아. 저장 중인 작업은 누가 맡고, 돌아왔을 때 목록에 어떤 결과가 보여야 하는지 설계해줘.
```

## 화면을 떠난 뒤 도착한 습관 저장 응답

이 예제의 제품 요구는 편집 화면을 떠난 뒤에도 저장을 끝내는 것이다. 앱이 이미 쓰는 상태관리 도구에서 편집 화면보다 오래 사는 소유자가 작업을 맡는다. 저장소는 쓰기와 지속되는 목록 데이터를, 편집 화면은 보이는 대기·오류 상태만 맡는다. 저장 작업에 고정 ID를 주어 재시도해도 습관이 중복 생성되지 않게 한다. 재시도가 성공한 뒤 도착한 이전 시도의 실패 응답은 그 작업의 결과를 바꾸지 못하게 한다. 닫힌 편집 화면은 응답을 받아도 이동하거나 알림을 띄우지 않는다. 목록은 저장소 데이터를 관찰한다.

| 제어한 사건 순서 | 저장소와 목록 | 닫힌 편집 화면 |
|---|---|---|
| 저장 누름 → 화면 이탈 → 지연된 성공 | 저장된 습관 1건, 목록 1행 | 화면 이동·알림 없음 |
| 저장 누름 → 화면 이탈 → 실패 → 재시도 성공 | 저장된 습관 1건, 목록 1행 | 화면 이동·알림 없음 |
| 첫 요청 보류 → 타임아웃 → 재시도 성공 → 첫 요청의 실패 응답 | 저장된 습관 1건, 목록은 성공 상태 유지; 오류·미저장 상태로 돌아가지 않음 | 화면 이동·알림 없음 |

응답 완료 순서를 제어하는 가짜 저장소로 단위 테스트에서 위 세 순서와 작업 ID·최종 상태를 확인한다. 위젯 테스트는 화면 이탈 뒤 목록 표시와 닫힌 화면의 부작용 부재를 확인한다. 통합 확인은 실제 저장 경로에서 저장 후 다시 연 목록을 확인한다. 프로세스 종료 후 복구는 제품이 요구할 때 따로 설계한다.

## 설치

[스킬 ZIP 다운로드](https://github.com/Ddrubok/flutter-app-architecture/releases/latest/download/flutter-app-architecture.zip) 후 Codex 스킬 폴더에 압축을 풉니다. 기본 위치는 `~/.codex/skills`이고, `CODEX_HOME`을 설정했다면 `$CODEX_HOME/skills`입니다. 압축 파일 안에 이미 `flutter-app-architecture` 폴더가 들어 있습니다. 설치 후 `flutter-app-architecture/SKILL.md`에서 지침을 확인할 수 있습니다.
